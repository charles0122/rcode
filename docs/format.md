# RCode v3：36 / 54 / 72 线，L / M / Q / H

借鉴腾讯公开的版本与纠错分级思路：https://developer.cloud.tencent.com/article/1005027 。采用自有几何、字节帧和 Reed–Solomon 参数，不兼容微信码。

## 容量与纠错

采用 128×128 逻辑画布、22 个径向格、定位点保留区、中央 Logo 留白和掩码。36/54/72 线分别产生 696/1040/1380 个格，因此一个码字可用 87/130/172 字节（不足一个字节的尾部格填零，再 XOR 掩码）。

设码字长为 n、档位目标比例为 p，则可纠正未知位置错误字节数 t=ceil(n×p)，RS 校验长度为 2t，内容容量为 n−2t−12。比例的分母为包括校验区的整个码字，不表示图像可遮挡面积。

| 线数 | 码字字节 | L 容量/校验 | M 容量/校验 | Q 容量/校验 | H 容量/校验 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 36 | 87 | 57/18 | 47/28 | 31/44 | 13/62 |
| 54 | 130 | 92/26 | 78/40 | 52/66 | 26/92 |
| 72 | 172 | 124/36 | 108/52 | 74/86 | 38/122 |

## 帧

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII RADC |
| 4 | 1 | 格式版本 3 |
| 5 | 1 | 线数 36、54 或 72 |
| 6 | 1 | 等级 L=0、M=1、Q=2、H=3 |
| 7 | 1 | 内容实际字节数 |
| 8 | capacity | 原始内容，不足补零 |
| 8+capacity | 4 | 此前全部帧字节 CRC32，大端 |

整个帧通过指定校验长度的 `reed-solomon 0.2.1` 编码，原始数据后附校验。字段、补零、CRC 和档位一致性均必须验证。线数和纠错元信息与内容一起受 RS 保护。

映射、掩码、坐标及字节位顺序构成当前格式。视觉比例依据用户提供的小程序码参考图：四个定位圆均采用外半径 5.2、白色开口半径 3.5、中心点半径 1.1，直径约占码盘直径 9.2%。36/54/72 线分别采用 2.0/1.8/1.4 的放射线宽度，圆头与孤立黑点半径分别为 1.0/0.9/0.7。线数越密，笔画越细，以保留内圈间隙。圆点样式沿用圆形笔画，但为避免径向重叠，半径限制为 0.55；直径 1.1，相邻采样中心间距 1.5，保留 0.4 的径向留白。PNG 与 SVG 共用参数。采样位置、保留区、内容容量和码字不变。

掩码按槽位索引 `i` 独立计算：令 `x = (i as u32) + 0x9e3779b9`（32 位回绕），依次执行 `x ^= x >> 16`、`x *= 0x7feb352d`、`x ^= x >> 15`、`x *= 0x846ca68b`、`x ^= x >> 16`（乘法均为 32 位回绕）；最终 `x & 1` 为掩码位。码字按槽位顺序逐位取高位优先，再与掩码位异或。

内圈增加固定的非数据轮廓填充，使所有放射线的可见内缘位于半径 22 的同一圆周。放射线样式的圆头线段中心从半径 22 加各版本笔画半径的位置开始：首个数据格为黑时接至半径 25；为白时止于半径 23.2。圆点样式在半径 22.55 放置半径 0.55 的固定点，同样保持可见内缘半径 22。中央 Logo 仍裁剪在半径 20 内。所有数据采样点、码字、容量和解码规则不变，轮廓填充不消耗纠错预算。

解码器通过四个相同的定位点估计单应变换，在几何校验后有限枚举 12 种线数与纠错档位组合；只有纠错后的完整帧验证通过才接受，不需要用户提供线数或等级。定位点按 TL、TR、BR、BL 的周界顺序求解，公开 landmarks 按 TL、TR、BL、BR 返回。

## API

`Profile::new(spokes,EccLevel)` 验证线数，提供 `capacity()`、`correctable_bytes()`、`parity_bytes()`。`encode(payload, profile)` 按指定档位编码。`DecodeResult.profile` 和 `Symbol.profile` 始终包含对应的 `Profile`。

CLI 与网页默认采用 72 线 M 档。API 编码请求新增 `spokes`、`ecc`，响应新增 `profile`；`GET /api/profiles` 返回 Rust 核心计算的容量，网页不重复维护容量表。超过选定档位容量直接报错，不截断内容，也不悄悄更换档位。
