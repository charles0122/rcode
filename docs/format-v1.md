# RadialCode v1

本协议为本项目自行定义的开放码制。视觉与定位思路参考腾讯的小程序码设计文章：https://developer.cloud.tencent.com/article/1005027 。不兼容腾讯私有协议。

## 帧和纠错

所有帧固定 138 字节，偏移从 0 开始：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `RADC` |
| 4 | 1 | 版本 `1` |
| 5 | 1 | 内容长度，0–128 字节 |
| 6 | 128 | 原始内容，不足部分必须补零 |
| 134 | 4 | 前 134 字节的 CRC-32/ISO-HDLC，大端 |

使用 `reed-solomon 0.2.1` 的 GF(256) 编码器 `Encoder::new(64)`：将 64 字节校验附加在帧之后，得到 202 字节系统码字（缩短 RS 码）。有限域使用本原多项式 `0x11d`，生成元 2，生成多项式的根从 2^0 开始。字节按高位优先展开为 1616 位。固定空内容帧 CRC 为 `53 56 a5 b7`。译码后必须验证 magic、版本、长度、补零和 CRC；纠错失败或校验失败均不得返回内容。

## 几何与映射

逻辑画布为 `[-64,64]×[-64,64]`，x 向右、y 向下。PNG/SVG 像素位置为 `(逻辑坐标+64)×输出尺寸/128`。

定位点依次为 `(-34,-34)`、`(34,-34)`、`(-34,34)`、`(34,34)`。前三个绘制前景色半径 8 圆、白色半径 4.8 圆、前景色半径 1.6 圆；第四个省略中心圆。中央 Logo 裁剪在半径 20 的圆内，半径 23 内留白。

按放射线 s=0..95、径向格 r=0..21 的顺序产生位置：

```text
angle = -PI/2 + 2*PI*s/96
radius = 25 + 1.5*r
x = radius*cos(angle)
y = radius*sin(angle)
```

排除与任一定位点距离严格小于 10 的位置，得到 1828 个格。前 1616 格装码字，其余 212 格原始值固定为零。单个 RS 块不做位级交织。

所有格（包括填充格）与以下固定掩码 XOR。运算使用无符号 32 位整数和溢出回绕，index 为排除保留区后的格序号：

```text
x = index + 0x9e3779b9
x ^= x >> 16
x *= 0x7feb352d
x ^= x >> 15
x *= 0x846ca68b
x ^= x >> 16
mask = (x & 1) != 0
```

1 为前景，0 为白。圆点半径 0.5；放射线样式仅连接同一放射线上径向序号连续且同时为 1 的相邻格，线宽 1、圆头。不得跨越保留区连接。

## 解码约定

从原始图像检测三个牛眼，拟合保持方向的相似变换（平移、旋转、等比缩放），验证第四圆环；根据定位点黑白采样确定阈值。采样各格中心邻域，逆掩码、组字节、RS 纠错并验证帧。返回定位坐标始终对应输入原图。解码不依赖文件名、PNG 元数据或中央 Logo。

PNG/JPEG 输入限定 8 MiB、1600 万像素。图像定位损坏或变换估计错误不能由 RS 自动修复。超过 32 个错误字节不保证恢复；CRC 提供额外完整性检查，但不作为安全认证。
